# Equipment Fault Prediction

Predicting whether a machine is about to fail from its sensor readings
(temperature, vibration, pressure, rpm, hours since last service). Faults are
rare, so the project is mostly about scoring models properly: accuracy hides
the problem, so I use precision, recall and F1 instead.

## Tools

Python, pandas, scikit-learn, matplotlib.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate      # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## How to run

The dataset, trained models and results are already included. To rebuild:

```bash
python src/make_data.py    # creates data/readings.csv
python src/train.py        # trains the models, saves scores and a plot
```

Run both from the project folder.

## About the data

The readings are generated by `src/make_data.py` (with some missing values on
purpose). They are fake, so the scores only show that the pipeline works. To
use real measurements, save them as `data/readings.csv` with a `fault` column.

## Models

- Logistic regression (scaled, class weights)
- Random forest (class weights)
- Gradient boosting

Missing sensor values are filled with the column median.

## Results

25% held-out test set (3,750 readings, about 8.6% faults). Also in
`results/scores.csv`, with a confusion matrix in `results/confusion_matrix.png`.
Trained models are in `models/`.

| Model | Precision | Recall | F1 |
|-------|-----------|--------|----|
| Logistic regression | 0.328 | 0.836 | 0.471 |
| Random forest | 0.412 | 0.728 | 0.526 |
| Gradient boosting | 0.673 | 0.433 | 0.527 |

F1 is almost the same for the forest and boosting, but they behave very
differently: the forest catches more faults and raises more false alarms,
while boosting is the opposite. Which one is better depends on what a missed
fault costs compared with an unnecessary inspection. The data is generated, so
treat this as a demo, not a finding.
